I reviewed the live UI from source (I didn't launch the app — native Avalonia windows can't be captured from the browser tools, so this is a code-level review, not a visual one).

## P0 — the checkout path is broken in ways a cashier hits in the first minute

**1. CHARGE never re-enables.** `PayCommand` is gated on `CanPay` (bill has ≥1 line), but nothing ever calls `PayCommand.NotifyCanExecuteChanged()` when lines change — only `AddProductCommand` and the two preview commands get notified (`OrderSelectionViewModel.cs:322-325`, `:453`, `:590`). A `[RelayCommand(CanExecute = …)]` doesn't observe property changes on its own, so the button stays disabled after the first item is added.

**2. "Hoàn tất thanh toán" has the same stale-enable problem.** `OnPaymentAmountChanged` / `OnIsSplitPaymentChanged` / `OnPaymentEntriesChanged` raise `OnPropertyChanged(nameof(CanCompletePayment))`, which updates the binding but not the command's `CanExecute` (`:164-171`). You need `CompletePaymentCommand.NotifyCanExecuteChanged()` there too.

**3. Selection state is invisible.** Payment method tiles (`Card/Cash/QR/Other`) and the Dine-in / Takeaway / Delivery pill are static styles — clicking them sets `SelectedPaymentMethod` / `ServiceType`, but nothing binds `IsChecked` or background back to the buttons. "Dine-in" just *looks* permanently selected because it's hardcoded. The cashier gets zero confirmation of two of the most consequential choices on the screen. (You already have `EqualityToBrushConverter` for exactly this — it's used in `ProblemReportsView` but not here.)

**4. The layout breaks at the screen sizes the app itself offers.** `OrderSelectionView` uses `ColumnDefinitions="*,520"` for the bill panel and fixed `Width="200"` product cards in a 4-column `UniformGrid` with `HorizontalScrollBarVisibility="Disabled"`. That needs ~864px for the grid alone, so at the 720 preset (1280 wide) the fourth column is clipped, and at the 480 preset (854×480, `UiSizePresets.cs`) the sales screen is unusable. `MainWindow` even allows resizing down to `MinWidth="640"`. Use a proportional bill column (`2*,Auto` with `MaxWidth`) and star-sized cards.

## P1 — flow and feedback gaps

- **No empty-cart state.** Every other list in the app has one (`InventoryView`, `OrderHistoryView`, `AuditLogView`…). The bill body is just blank, and the totals/footer show `0 ₫` above a live CHARGE button.
- **No feedback anywhere.** There's no toast/snackbar service in the project. Hold, Recall, Apply coupon, Save customer, void, and print all complete silently — and `ApplyCoupon` returns silently when the code doesn't match. A cashier can't tell success from a dead click.
- **Held bills are invisible until you open the dialog.** Hold/Recall buttons have no count badge, and the recall list has no empty state.
- **Delivery fields are always shown**, for Dine-in and Takeaway too, which pushes the cart lines down and invites bad data.
- **Tables never wrap or scroll** — an `ItemsControl` with a horizontal `StackPanel`, so a real café's 20+ tables overflow the panel.
- **Search is narrower than its promise.** Watermark says "Search menu items, variants, or codes…" but the filter only does `Name.Contains` (`:205-207`); no code/barcode, no clear button, and the filter icon button next to it has no command at all.
- **Amount entry is a bare `TextBox`.** No numeric entry, no quick-cash buttons (50k/100k/200k/500k), no change-due shortcut — the slowest part of a cash sale.
- **Split payment gives no running "còn thiếu" indicator.** The footer only reports the split total, and the only signal that it doesn't match is a disabled button.
- **Receipt/Tags print duplicates.** `CompletePaymentAsync` already prints receipt + kitchen ticket and opens the drawer (`:551-555`), so the separate Receipt/Tags buttons are a second, different mental model.
- **Bill tabs show only "Bill N"** (or a table name) with no amount or item count — indistinguishable tabs on a busy bar, and labels can collide after closing bills (`:259`).

## P2 — visual system and consistency

- **Two languages on the same screen.** The app is `vi-VN` (`Program.cs:31`) and nav is localized, but the entire sales screen is English ("Subtotal", "Tax", "CHARGE", "Merge", "Void", "Drink Tags Preview") while the payment dialog is Vietnamese ("Thanh toán", "Tổng thanh toán", "Tiền thừa"). That single inconsistency does more damage to perceived quality than any pixel issue. Localization is also limited to 25 nav keys — the strings in views aren't in the `.resx` at all.
- **Light theme does nothing.** `ThemeApplier` only sets `RequestedThemeVariant`, but `Theme.axaml` brushes are plain (not `ThemeDictionaries`), and views consume them as `StaticResource`. Settings offers a theme switch that leaves all custom surfaces dark.
- **Contrast:** `SecondaryBrush #8B6B4A` used for 12px section labels is ≈3.6:1 on `#1A1A1A` (fails AA 4.5:1); `PrimaryBrush` note text on `SurfaceMutedBrush` is ≈4.2:1 and also fails at 11px.
- **Touch targets:** quantity steppers, service pills, table chips and the row action buttons are 28–32px on a touch POS; 44px is the practical floor (your CHARGE button at 64px is right).
- **No accessibility layer:** zero `AutomationProperties`, no access keys, icon-only buttons rely on `ToolTip` alone.
- **Dialog inconsistency:** payment uses `ModalOverlay`, everything else hand-rolls a `Border` overlay. None of them close on backdrop click or Esc (only the customization dialog has `KeyBindings`), and none trap focus.
- **Dead code in the design system:** `ShellView`/`ShellViewModel` (260px sidebar) are referenced nowhere — the live shell is `BentoHomeView` → `ModuleHostView`. `Colors.axaml`, `ColorsDark.axaml`, `Spacing.axaml`, `Radius.axaml`, `Typography.axaml` are never merged (values are duplicated inline in `App.axaml`), so there are two sources of truth for the token system.
- **Currency formatting is split** between `{0:N0} ₫` (order screen) and `{0:C0}` (`Components.axaml`).

## Worth keeping

The token palette and dark surfaces are coherent, the totals hierarchy (Subtotal → Tax → Discount → Total) is well ordered, the customization dialog is genuinely good (big targets, Enter/Esc, live line total), and the product card price badge reads well. The bones are solid — the problems are state feedback, responsive sizing, and string consistency.

**My fix order:** (1) command notifications, (2) selection visuals on payment/service, (3) responsive bill panel + card widths, (4) empty cart + a toast service, (5) Vietnamese strings across the sales screen.
