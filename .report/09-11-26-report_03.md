# UI redesign and component unification — POS.Avalonia

Scope: the home screen, the colour theme, the button system and the shared
components, plus the crashes that appeared once home tiles became clickable.

Method: source changes verified with `dotnet build`, a throwaway harness that
constructs every view class (27/27), a DI audit over all 22 home modules, a
runtime probe that renders real buttons and reads back the applied brushes, and
the Windows event log for crash stacks. **I did not visually inspect the app** —
native Avalonia windows cannot be captured here — so pixel-level judgement (tile
size, density, type feel) is still open.

> **Palette superseded.** §2 describes the first pass (warm graphite, olive
> accent). It was replaced by the cool slate / deep-teal system now in
> `Theme.axaml`; `docs/design-system.md` carries the live values, and the
> contrast table in §2 is the record for that first pass.

## 1. Home is one wall of square modules

- The `VẬN HÀNH / QUẢN LÝ / HỆ THỐNG` group labels, their rules and the
  three-section split are gone. `BentoHomeView` is a header plus a single
  `ItemsControl` over one ordered `Tiles` collection of 22 modules.
- Every tile is 1:1: `BentoGridPanel` gained `SquareCells`, so row height is
  derived from the measured column width instead of a fixed 116 px row. Columns
  step `2 / 3 / 4 / 5 / 6 / 7 / 8` at 520 / 760 / 1000 / 1240 / 1480 / 1720, which
  keeps tiles around 180–230 px rather than four huge slabs.
- Tiles are real buttons now (hover border → primary, tinted icon plate,
  keyboard focus ring, hand cursor) instead of non-clickable `Border`s, and they
  navigate through `OpenTileCommand`.

## 2. Theme

Warm graphite canvas, off-white ink, muted olive as the single brand accent,
terracotta reserved for attention. `Theme.axaml` keeps 108 keys per variant
(`Dark` / `Light`) so a variant switch is total.

Measured contrast (minimum per variant, AA text = 4.5:1):

| Variant | Lowest pair | Ratio |
| --- | --- | --- |
| Dark | Secondary on Surface | 5.51 |
| Light | Warning on Surface | 5.12 |

`OnPrimary` was introduced because a light sage primary cannot carry white text:
dark theme primary `#9BAF7D` takes `#12130F` ink, light theme primary `#52653D`
takes `#FBFBF7`.

## 3. Buttons: one system, chosen by meaning

`Styles/Buttons.axaml` is now the only *shared* button definition; the button
styles that were in `AppControls.axaml` were removed. Views choose a variant
instead of painting a button, with a handful of exceptions listed below.

- Variants: `primary`, `secondary`, `ghost`, `danger`, `link`.
- Sizes: `sm`, `lg`, `icon`; modifier `muted`.
- Selectable tile: `choice` + a bound `selected` class, used for payment method
  and service type.
- States (hover, pressed, disabled, focus-visible) live in the same file.

Migration across all views:

| Metric | Before | After |
| --- | --- | --- |
| Buttons carrying a variant class | 62 | 164 |
| Buttons still styled outside the system | — | 28 |
| Buttons painting `Background` inline | 43 | 12 (intentional) |
| Inline `CornerRadius` | 17 | 0 |
| Inline `Foreground` | 54 | 4 |
| Literal hex colours applied in views | 2 | 0 |

The 12 remaining inline backgrounds are all state, not styling: filter and
priority chips whose fill comes from `EqualityToBrushConverter`, the 64×64
MusicPlayer transport button, and the tinted refund/remove buttons.

The remaining 28 of 192 buttons carry no variant: the home tile
(`Classes="bento-tile"`, a container style of its own), the style-guide demo
buttons, and buttons that still set their own `Padding` or `Background` in
BentoHomeView.axaml (1), InventoryView.axaml (1), MenuManagementView.axaml
(4), MusicPlayerView.axaml (1), OrderHistoryView.axaml (1),
OrderSelectionView.axaml (1), ProblemReportsView.axaml (8),
RecipeBookView.axaml (2), SettingsView.axaml (3), StyleGuideView.axaml (4),
WasteLogView.axaml (2). Separately, two views — the category list in Menu
Management and the table rows in Order History — still declare a local
`Button.Styles` block for their hover fill, even though those buttons do carry
`ghost`. Folding both cases into a `row` variant is the next piece of the
migration.

## 4. Shared components

- **New `controls:EmptyState`** (`Icon` geometry, `Title`, `Hint`, optional
  action). Adopted in Inventory, Order History, Audit Log and Discount
  Management, replacing four hand-rolled variants that had drifted apart.
- **`controls:PageTitle`** gained `Subtitle` and token typography; 13 views use it.
- `Card`, `KpiCard`, `StatusBadge`, `ModalOverlay` remain the shared
  card / KPI / chip / dialog primitives.
- `.rules/design.md` §2.0 documents the library and the "compose, never re-draw"
  rule.

## 5. Defects found and fixed

Ordered by severity, all reproduced before fixing.

**P0 — Orders module killed the process.** The event log showed
`Unable to resolve service for type 'IKitchenDisplayService'` while activating
`OrderSelectionViewModel`. The interface existed with **no implementation and no
registration**, so opening POS Bán hàng or Lịch sử đơn threw on the UI thread and
terminated the app. Fixed by adding `Services/KitchenDisplayService.cs` (real
kitchen ticket from order + lines, with table, service type, elapsed time, late
flag) and registering it.

**P0 — `OrderSelectionView` threw on construction.** `InvalidCastException` on a
`Border` with `BoxShadow="{StaticResource ShadowDialog}"`: the rewritten theme
defined `Shadow*` tokens as `<x:String>`, and a string cannot be cast to
`BoxShadows`. All seven shadow tokens are now typed `<BoxShadows>`.

**P1 — Debug tile resolved to nothing.** `DebugViewModel` was never registered;
the tile opened an empty module. Now `AddTransient<DebugViewModel>()`.

**P1 — `Spacing12` was referenced but never defined** by `DashboardView` and
`AiChatView` (silently zero spacing). Added to `Styles/Spacing.axaml` and
`App.axaml`.

**P1 — CHARGE label collided with the amount.** The new base button style forced
`HorizontalContentAlignment=Center`, so the inner `*,Auto` grid measured at its
minimum width. Removed from the base; CHARGE sets `Stretch`.

**P1 — disabled buttons were illegible.** `Opacity 0.45` washed the whole button
out. Disabled is now a real state: `SurfaceMuted` fill, `Border` hairline, muted
ink, full opacity.

**P1 — payment method and service type had no visible selection.** Added the
`choice` + `selected` classes, `StringEqualsConverter`, and bound them to
`SelectedPaymentMethod` / a new `SelectedServiceType` view-model property
(previously the per-bill string existed but nothing raised change notifications).

## Still open

1. **CHARGE and "Hoàn tất thanh toán" still never re-enable** — `PayCommand` /
   `CompletePaymentCommand` do not call `NotifyCanExecuteChanged()` when bill
   lines or payment amounts change (report_01, P0 #1/#2). The new disabled style
   makes the stuck state more visible, not less. This is the next thing to fix.
2. **28 buttons are not on the system yet** (see the breakdown
   above), plus two views that still declare their own `Button.Styles`.
3. **`StyleGuideView` is out of date**: it prints twelve hex strings from the
   previous palette as text labels (`#D4E5D2`, `#6B8E6B`, …), shows demo buttons
   with local styles instead of the real variants, and so contradicts the live
   theme. It should be rebuilt from the tokens and variants, or deleted.
4. **No visual inspection.** Tile proportion, choice-tile height (72 px) and the
   density of the module wall need a human look at a running window.
5. **Mixed UI language** on the checkout screen (English labels inside a `vi-VN`
   app) is unchanged from report_01.

## Worth keeping

The token layer is coherent and now single-sourced, the home wall reads as one
surface instead of three sections, and the button system means a new screen can
be built without inventing visual styles. The `choice`/`selected` pattern and the
`EmptyState`/`PageTitle` controls are the reusable pieces future screens should
start from.
